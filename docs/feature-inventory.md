# Meta Player 功能清单

本文档用于梳理当前版本已经落地的产品能力，方便后续做：

- 对外宣传文案整理
- 功能级授权方案设计
- 后续版本规划与权限分层

说明：

- “已实现”表示代码中已经存在可用 UI 和对应数据流。
- “部分实现”表示主流程已通，但仍有明显占位或能力缺口。
- “预留能力”表示界面或配置已预留，但当前版本尚未真正打通。

## 一、产品定位

Meta Player 当前不是单一播放器，而是一个面向本地素材处理的桌面工作台，核心能力覆盖：

- 项目管理
- 本地素材导入与管理
- 视频播放与定位
- 素材级标记管理
- AI 剧情大纲提取
- 剧情片段检索
- 本地持久化存储
- 设备指纹与授权状态展示

适合当前对外描述为：

> 一款面向视频素材整理与剧情分析的桌面工作台，支持项目管理、素材导入、AI 大纲提取、剧情检索和关键时间点标记。

## 二、当前已实现功能

### 1. 项目管理

状态：已实现

已支持：

- 新建项目
- 编辑项目名称与描述
- 删除项目
- 项目搜索
- 查看每个项目关联的素材数量
- 从首页进入指定项目工作台

业务价值：

- 把素材、播放器、剧情大纲和标记能力组织到项目维度
- 适合按客户、题材、节目、专题进行管理

可用于宣传的表达：

- 支持多项目并行管理
- 支持按项目组织素材与剧情分析结果
- 支持快速搜索和切换项目

### 2. 素材导入与素材库管理

状态：已实现

已支持：

- 从本地导入多个视频或图片素材
- 导入后自动加入当前项目
- 素材库列表展示
- 按素材标题、剧情简介搜索素材
- 删除素材
- 维护素材的剧情简介
- 维护素材的 SRT 字幕文本

当前导入策略已支持：

- 托管导入：复制文件到应用素材目录
- 引用导入：直接引用用户原始文件路径
- 内容哈希去重：重复导入相同素材时不会重复创建记录

业务价值：

- 既适合希望节省磁盘空间的引用模式，也适合希望由应用统一托管的复制模式
- 适合逐步为素材补充结构化文本信息，为 AI 提取和检索做准备

可用于宣传的表达：

- 支持本地多素材批量导入
- 支持托管式和引用式两种素材接入方式
- 支持素材去重与统一管理
- 支持为素材补充剧情简介与字幕文本

### 3. 视频播放与定位

状态：已实现

已支持：

- 播放当前选中的视频素材
- 基于 Electron 本地播放器组件进行视频渲染
- 支持外部调用跳转到指定时间点
- 支持播放器时间变化回调
- 支持根据容器尺寸自适应播放器区域
- 在播放器中展示时间点高亮提示

当前限制：

- 图片素材不能在该播放器面板中播放，只能作为非视频素材存在
- 播放器设置按钮目前仅为 UI 入口，未接具体设置项

可用于宣传的表达：

- 支持桌面端本地视频播放与时间定位
- 支持关键时间点高亮辅助浏览
- 支持与剧情检索、标记管理联动跳转

### 4. 素材级标记管理

状态：已实现

已支持：

- 为当前素材添加标记
- 编辑已有标记内容
- 删除标记
- 点击标记跳转到对应时间点
- 创建标记时对时间点进行微调
- 标记列表按时间顺序展示

当前交互特点：

- 标记弹窗支持拖动
- 支持以 1 秒和 0.1 秒粒度微调标记时间

业务价值：

- 可用于记录镜头说明、剪辑点、重点内容、问题点、备注信息
- 是后续切片、审片、协作标注的基础能力

可用于宣传的表达：

- 支持关键时间点标记和注释管理
- 支持标记与播放器联动定位
- 支持精细化时间微调

### 5. AI 剧情大纲提取

状态：已实现

已支持：

- 基于剧情简介和 SRT 字幕文本调用 OpenAI 兼容接口
- 让模型输出结构化剧情场景列表
- 对模型返回内容进行 JSON 解析、校验和规范化
- 将结果映射为场景列表在右侧大纲面板展示
- 提取失败时展示错误信息

当前输出结构包含：

- 场景标题
- 场景描述
- 开始时间
- 结束时间
- 场景时长
- 场景跳转时间

业务价值：

- 把原始视频内容转成可浏览、可检索、可跳转的剧情结构
- 为后续的内容理解、片段定位、内容复用提供基础

可用于宣传的表达：

- 支持 AI 自动提取剧情大纲
- 支持将长视频拆解为结构化场景片段
- 支持从字幕与简介生成可浏览的剧情结构

### 6. 剧情大纲浏览

状态：已实现

已支持：

- 按场景列表浏览剧情大纲
- 展开和收起场景详情
- 显示时间范围和时长
- 选中当前场景
- 当前场景自动滚动到可视区域

当前限制：

- 场景编辑按钮目前只有 UI 入口，尚未接实际编辑能力
- 场景拖拽手柄是视觉预留，尚未实现排序调整

可用于宣传的表达：

- 支持结构化剧情场景浏览
- 支持按场景查看时间范围与详细描述
- 支持剧情片段快速导航

### 7. 剧情检索

状态：已实现

已支持：

- 在项目范围内搜索剧情片段
- 返回匹配的素材、场景、时间范围和文本片段
- 点击检索结果联动播放器跳转
- 索引不存在时自动尝试建立片段索引

当前支持三种检索模式：

- 关键词检索
- 大模型排序检索

当前降级策略：

- 大模型搜索失败时自动退回关键词检索

业务价值：

- 从“看视频找片段”变成“搜剧情找片段”
- 更适合长视频、素材库规模逐步扩张后的片段定位

可用于宣传的表达：

- 支持剧情片段搜索与定位
- 支持关键词检索和大模型搜索策略
- 支持搜索结果一键跳转到对应视频时间

### 8. AI 与系统设置

状态：已实现

已支持：

- 设置素材保存目录
- 设置默认托管导入开关
- 配置 OpenAI 兼容 API Base URL
- 配置 API Key
- 配置剧情提取模型
- 配置剧情搜索模式
- 配置大模型搜索模型

业务价值：

- 让应用可适配不同模型服务提供方
- 让不同客户按自己的部署环境进行接入

可用于宣传的表达：

- 支持 OpenAI 兼容接口接入
- 支持按需切换剧情检索方案
- 支持素材存储策略配置

### 9. 本地持久化

状态：已实现

已支持：

- 使用本地 SQLite 存储项目、素材、标记、剧情大纲、索引和设置
- 使用本地 SQLite 存储项目、素材、标记、剧情大纲和设置
- 应用重启后保留数据
- 启动时统一加载持久化快照
- 通过本地 API 统一访问持久化数据

当前持久化对象包括：

- 项目
- 素材
- 项目与素材关联
- 素材文本信息
- 剧情大纲
- 大纲片段索引
- 标记
- 应用设置

业务价值：

- 适合桌面端离线工作流
- 减少浏览器本地存储拼装带来的不稳定性

可用于宣传的表达：

- 支持本地数据库持久化
- 支持素材、项目与分析结果统一留存
- 支持桌面端稳定数据管理

### 10. 本地媒体访问能力

状态：已实现

已支持：

- 通过本地 API 路由访问素材文件
- 避免前端直接读取 `file://` 导致的浏览器限制
- 图片与视频通过统一媒体访问通路被前端消费

业务价值：

- 为后续缩略图、预览、导出和媒体处理能力提供统一入口

### 11. 设备指纹与授权信息展示

状态：部分实现

已支持：

- 生成本机设备指纹
- 在用户页面展示设备指纹
- 一键复制设备指纹
- 展示授权状态
- 展示按功能粒度的授权清单

当前限制：

- 目前展示的是本地授权快照骨架
- 尚未真正接入远端授权后台
- 尚未对业务功能做真实拦截

业务价值：

- 为后续按设备授权和按功能授权打下基础

## 三、已部分实现的能力

### 1. 图片素材支持

状态：部分实现

当前情况：

- 图片可以导入并作为素材记录保存
- 图片可以通过统一媒体路由访问
- 但当前播放器面板不支持图片预览工作流

### 2. 设备授权体系

状态：部分实现

当前情况：

- 已有本机指纹生成和展示能力
- 已有功能级授权模型
- 尚未落地后台注册、签名、同步、吊销、离线宽限等完整链路

## 五、适合做授权拆分的功能域

如果后续要做功能级授权，建议按“用户能感知到的业务能力”来分，而不是按技术实现分。当前版本建议拆成以下授权域：

### A. 基础工作台

建议包含：

- 项目管理
- 素材库浏览
- 本地持久化读取
- 用户页与设备信息查看

适合：

- 免费版
- 试用版
- 基础版

### B. 素材管理增强

建议包含：

- 素材导入
- 素材删除
- 剧情简介编辑
- SRT 字幕编辑
- 托管导入配置

### C. 播放与标记

建议包含：

- 视频播放
- 标记创建
- 标记编辑
- 标记删除
- 标记跳转定位

### D. AI 剧情提取

建议包含：

- 调用 AI 提取剧情大纲
- 大纲结构化展示

### E. 剧情检索

建议包含：

- 关键词检索
- 大模型搜索
- 搜索结果跳转

### F. 高级 AI 配置

建议包含：

- AI Base URL 配置
- API Key 配置
- 模型配置
- 检索模式切换

- 本地素材统一导入与管理
- 支持托管导入与引用导入
- 支持视频关键时间点标记
- 支持 AI 自动提取剧情大纲

- 支持 OpenAI 兼容接口接入
- 支持桌面端本地数据库持久化

## 七、不建议当前直接宣传为“已完成”的点

以下内容容易造成预期偏差，当前不建议对外表述为正式能力：

- 完整视频剪辑
- 时间线编辑
- 切片导出
- 图片工作流完整支持
- 完整后台授权系统
- 剧情场景编辑与重排
- 安全加密凭据存储

## 八、下一步建议

为了方便你后续设计详细授权方案，建议下一步直接基于本文档做一张“功能-授权级别矩阵”，至少包含：

- 功能名称
- 是否默认开放
- 授权类型
- 是否允许试用
- 是否允许离线
- 是否需要联网校验
- 后台是否可单独禁用
- 到期后的降级行为

如果继续推进，建议优先设计这几类功能的授权策略：

1. 素材导入与删除是否属于基础权限
2. 标记能力是否单独授权
3. AI 大纲提取和剧情检索是否拆成两个授权项
4. 仅关键词搜索是否免费，大模型搜索是否高级版开放
5. AI 配置是否只对管理员或高级版开放
